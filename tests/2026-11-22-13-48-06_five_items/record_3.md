# 第 3 轮 · 第 5 条 ws 实时推送的延迟与消耗（量，太耗性能撤）

- **时间**：2026-11-22-14:57 → 15:00（jarvis 主 pid 12520，7860 LISTENING 归它；启动器 12640 3 MB 同一次启动）
- **场景**：列 `Win32_Process` 的 CommandLine 找真主 pid（第 195 处教训：不猜）；先量**无监视客户端** 60 s 基线（页上只有 about，WS 不在），再开 `http://127.0.0.1:7860/monitor?v=71`、装逐行到达延迟计数（丢前 10 条积压，第 195 处教训），量同一 60 s 的 CPU 与延迟。
- **期望**：ws 实时推送要真的更快，且量消耗；太耗性能撤掉。
- **实际**：基线（无客户端）60 s CPU = 214.484375 − 208.1875 = **6.296875 s**；有客户端 60 s CPU = 226.546875 − 219.921875 = **6.625 s**；增量 **0.328 s CPU / 60 s ≈ 0.55% 单核**（100 ms 节流、每拍 ≤20 行、无客户端时 0.1 s 直接 skip、只发日志增量不重发快照）。推送：60 s 内 **21 个 chunk、21 行**，逐行到达延迟 **最小 0.5 / 最大 0.9 / 均 0.7 s**（100 ms 节流 + 服务端每拍 ≤20 行）；`ws.readyState 1`、console 0 条。
