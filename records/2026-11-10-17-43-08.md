## 现状勘察（开工前实测）

- **汉化残留**：上一批只汉化了「工具名」（`TOOL_LABELS`）。用户看到的 `我执行了 读取屏幕、点击坐标、输入文本：Typed: 证断` 里，冒号后的部分是**工具返回值首行**（`main.py::_tool_report` 取 `executed[-1][1].strip().split("\n")[0][:80]`），而各工具函数返回的是英文模板：`Typed: …`、`Pressed: enter`、`Clicked (x,y)`、`Unknown media action: …`、`Volume set to 20`、`Scrolled down 3` 等（`jarvis/tools/desktop.py`、`system.py`、`app_control.py` 等）。UI 的 `tool_result` 气泡显示的是同一段英文。要补全汉化，必须覆盖**返回值文案**（不能改 schema 里的英文参数名）。
- **ASR 现状**：`config.yaml` `stt: model small / device cuda(实际回退 cpu) / compute_type int8 / language zh`；`jarvis/stt.py::transcribe_audio` 调 `model.transcribe(audio, beam_size=5, language=lang)`，**没有 `initial_prompt`、没有 `vad_filter`、没有 `best_of/temperature` 回退**，`record_until_silence` 只给 16 kHz 单声道 float32 内存数组，**录音不落盘**，所以现在无法离线复现用户那句话做 A/B 比对。
- 已知相关现象（上一批登记）：whisper 小模型对中文短句倾向输出**繁体**（`[You] 我愛你`）、丢字（`你能看得见屏幕吗?` → `你能看的就`）。`language=zh` 已固定，`beam_size=5` 已设，因此优化空间在于：`initial_prompt`（引导简体 + 常用词表）、`beam_size/best_of` 提高、`vad_filter` 减少噪声块、以及**换 ASR 引擎**（中文专强的 sherpa-onnx paraformer / FunASR paraformer-zh，都是离线 CPU 方案）。

## 方案

1. **汉化补全**：把各 `tools/*.py` 返回的用户可听文案改成中文（`已输入文本：…`、`已按下：enter`、`已点击 (x, y)`、`已滚动：向下 3 格`、`音量设为 20` 等），工具内部协议字段（`name`/参数名/`args`）保持英文不变；`_tool_report` 与 UI `tool_result` 自动跟着变。逐文件列出改动点，避免动到 LLM schema。
2. **录音落盘**：`record_until_silence` 之后把 16 kHz int16 存 `.tmp/capture_<时间>.wav`（`.gitignore` 内，不 commit），日志打印路径 —— 这是做 ASR A/B 的前提，也让后续 ASR 问题可复现。
3. **ASR 优化（同引擎先榨）**：`transcribe` 加 `initial_prompt`（简体中文引导 + 本项目常用词：爱莉希雅/屏幕/点击/输入/时间/音量/浏览器…）、`beam_size` 5→10、`best_of=5`、`vad_filter=True`、`temperature` 回退；`condition_on_previous_text=False` 避免短录音漂移。离线 A/B：同一 wav 用新参数跑，比对文本。
4. **换引擎（若 3 不够）**：候选 **sherpa-onnx + paraformer-zh**（离线 onnx，CPU 快，中文短句精度显著优于 whisper small，带标点模型），或 FunASR paraformer-zh。先探测可安装性与模型可得性（`hf-mirror.com` 可达性、磁盘余量），评估表（体积/依赖/延迟/精度/是否联网）落盘，再经用户授权后切换。
5. **真人验证**：请用户依次说 3 句标准句（「你能看得见屏幕吗？」「现在几点了？」「把音量调到二十」），用落盘 wav 做 3 轮 A/B（旧参数 / 新参数 / 新引擎），每轮 record 里写明识别文本与差异。
