# 需求记录：修复 web2 profile 无法解析本地 bundle @local/dsh-my-presets

- 时间：2026-11-21-10-13-16（需求提出）
- 状态：实施中
- 关联测试：无
- 提出人：用户

## 现象

删除旧版本目录后，项目（JarvisAi）正常，但 DSH 启动报：

```
dsh: skipping profile bundle "@local/dsh-my-presets": Error: dsh: cannot resolve profile bundle
"@local/dsh-my-presets" from the dsh installation or C:\Users\楼听\.dsh\profiles\web2;
run 'dsh plugin --profile web2 install' if its dependency is not installed
```

## 根因（已实测确认）

1. `C:\Users\楼听\.dsh\profiles\web2\package.json` 的 `dsh.profile.bundles` 列出了 `@local/dsh-my-presets`，
   `dependencies` 写的是绝对路径 link：`link:C:/Users/楼听/Desktop/git/JarvisAi/dsh-my-presets`。
2. `node_modules/@local/dsh-my-presets` 是指向该 Desktop 路径的符号链接；旧版本目录被删 → 悬空链接。
3. DSH 解析 bundle 走 node 模块解析（`packages/boot/app-boot/src/profile.ts:resolveBundleDir`：
   从 dsh 安装锚点和 profile/package.json 两个锚点 `require.resolve('<pkg>/package.json')`），
   两处都解析不到 → **按设计跳过该 bundle**，DSH 正常启动，只是自定义预设（PTC-MY / 创造模式-MY）不挂载。
4. pnpm 把 link spec 存成相对路径（`pnpm-lock.yaml`：`link:../../../Desktop/git/JarvisAi/dsh-my-presets`），
   所以「绝对路径 + 删目录」就是本次故障的成因。

## 需求

把本地包收进 DSH home，让 profile 不再依赖工作区/Desktop 的绝对路径：

1. `dsh-my-presets` 与 `wow-kit` 已由用户拷贝到 `C:\Users\楼听\.dsh\profiles\web2\vendor\`（已核对：
   `package.json` 的 name 分别为 `@local/dsh-my-presets` / `wow-kit`，均带 `dsh.bundle.patch`）。
2. profile 的 `dependencies` 改为相对 link：`link:./vendor/dsh-my-presets`、`link:./vendor/wow-kit`。
3. 跑 `pnpm dsh plugin --profile web2 install`（即 profile 目录内 pnpm install），重建 node_modules 链接。
4. 重启 DSH，验证 bundle 真挂载、无 skipping 报错。

## 落盘与约定

- 生效副本现在是 `.dsh\profiles\web2\vendor\*`（live）；仓库内 `dsh-my-presets/` 成为源码备份，
  改预设后必须同步拷贝到 vendor，否则不生效。
- `C:\Users\楼听\.dsh` 在本会话工作区外，写入需要用户审批。
- 重启 DSH 由用户执行（会话内不能自杀式重启）。

## 方案

见上「需求」2-4 步；只读诊断已完成，无其他阻塞。
