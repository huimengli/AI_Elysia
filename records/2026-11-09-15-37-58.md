## 追加（2026-11-09-17-2x）需求 6：共用浏览器插件评估（三问，未装，待用户授权）

- 目录里已上架的候选（`mcp_connector_catalog` 本地货架）：`playwright`（Playwright · 浏览器自动化/页面检查）、`chrome-devtools`（Chrome DevTools · 调试/网络分析）；`firefox-devtools` 仅 macOS 验收，本机不适用。
- **候选 1：Playwright MCP（microsoft/playwright-mcp，`@playwright/mcp`，Apache-2.0，微软官方）**
  - 口碑：MCP 生态中最主流的浏览器服务器，官方维护、更新频繁、文档完善；社区使用量最大。
  - 恶意执行面：本地 `npx` stdio 启动，可执行 `node`（允许的可执行文件为官方 npm 包）；`postinstall` 只下载浏览器内核，不联网执行远程代码；无需管理员权限、无开机自启、无自定义 native host。
  - 数据外发：与本地 Playwright 驱动通信（loopback），**无云端中继**。共用浏览器的两条合法路径：`--extension`（Chrome 应用商店的 Playwright MCP Extension，让 MCP 附着到**用户正在使用的 Chrome**）与 `--cdp-endpoint http://127.0.0.1:9222`（用户 Chrome 以 `--remote-debugging-port=9222` 启动，仅回环）。两者都读写用户真实会话（登录态、Cookie、标签）→ 属**隐私敏感**，需用户知情。
  - 结论：**通过**（推荐 `--cdp-endpoint` 回环模式，最透明、无需商店扩展）。
- **候选 2：Chrome DevTools MCP（Google Chrome Labs，`chrome-devtools-mcp`）**
  - 口碑：Google 官方实验室项目，README 明确、迭代快，评分/口碑与 Playwright MCP 同级。
  - 恶意执行面：本地 `npx` stdio；无 postinstall 远程代码；无自启/管理员/native host。
  - 数据外发：仅 CDP 回环（可 `--browserUrl` 附着已运行的 Chrome），无中继。共享用户会话同上（隐私敏感）。
  - 结论：**通过**（与候选 1 等价，二者选其一即可，不建议同时装以免抢占同一 CDP 端口）。
- **候选 3：Browser MCP（λlabs browser-use / `browsermcp`）**
  - 口碑：流行度高，但架构含**云端 relay**（扩展 ↔ 厂商中继 ↔ MCP 客户端）。
  - 数据外发：页面内容/标签信息经厂商中继服务器 → **违反本规则「云端中继 = 拒绝」**。
  - 结论：**拒绝**（不安装，不配置）。
- 三问规则已写入 `progress.md`「浏览器共用插件评估规则」；本次评估结论追加于此。**安装/配置（`mcp_connector_configure`）在用户明确授权前不执行**（审批提示已关闭，此类动作会被自动拒绝）。
- 建议落地方式（待授权）：给用户 Chrome 加启动参数 `--remote-debugging-port=9222`，我用 `playwright` 连接器 `--cdp-endpoint` 附着；此后我驱动的页面就是**用户眼前的同一个 Chrome**，「对话不能实时出现」的双浏览器根因消除。
