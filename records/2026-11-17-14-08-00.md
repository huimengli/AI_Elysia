# 只听歌三件事的实现路径：用 CDP 控制页面 · 2026-11-17-14-08

接 `records/2026-11-17-14-01-00.md`。

## 实测发现（全部是亲眼截图，不推测）

1. **`m` 键盘快捷键无效**：在 jarvis 起的窗口里 `focus_window` + `press_key('m')` 两次，弹幕**照旧满屏**
   （`14-03-13_shot.png`、`14-04-18_shot.png`）→ B 站快捷键不可依赖
2. **控制条只在悬停时出现、约 2-3 秒自动隐藏**：裁剪 `y=655..760` 那条是**全黑**（`14-06-49_crop.png`，1058 字节）
   → 「裁剪控制条读时间」必须在指针停在控制条上的瞬间抓，不能事后补
3. **播完自动连播**：窗口标题从「私藏馆·稻香」→「情人节·爱情废柴」→「春节·本草纲目」，页地址也变成
   `BV1Sy4y1r7ZH`。这是 B 站播放列表 autoplay 在起作用（我 14:04 的单击/按键之后视频就换了两支）
   → **「播完关窗」必须先把 autoplay 关掉**，否则窗口永远在放下一支，永远等不到「播完」
4. **Route B 的坐标点击是有害的**（坐实 13:56 的怀疑）：在播放器/侧栏区点 3 次，把视频换掉了

## 实现路径（改法，不造新约定）

- **jarvis 起 Chrome 时加 `--remote-debugging-port=9333`**（只作用于 jarvis 自己的窗口与自己的
  `.tmp/chrome_profile`），用 CDP 直接驱动页面：
  - 读 DOM 找到**弹幕开关**、**清晰度菜单**、**autoplay 开关**、**播放进度**（`video.currentTime` / `video.duration`）
  - 用 DOM 点击/赋值，**不用视觉坐标、不用键盘注入**（两者都已被实测证明不可靠）
  - `video.ended` 事件 → 关掉 jarvis 自己起的窗口（pid 在 `.tmp/jarvis_browser_pids.json`，Q29 授权）
- **jarvis `.venv` 已有 `websockets` 包**（`.venv/Lib/site-packages/websockets/`），不需要新依赖
- 判据五项：**导航（标题/地址）→ autoplay 关 → 弹幕关 → 最低分辨率 → 时间前进 + 播完关窗**

## 边界（如实）

- CDP 端口只开在 jarvis 自己的 Chrome 上，**不碰你的窗口/你的 profile**；9333 仅监听 127.0.0.1
- 选择器**必须实测枚举**（我用 CDP 读 DOM 得到真实的按钮名），不猜
- 若 CDP 连不上（端口没开/页面结构变了）→ 如实报失败，**不降级成"看起来播放了"**

- **状态**：**已开工**（加端口 + CDP 客户端 + DOM 枚举）
