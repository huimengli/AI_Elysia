## 原始需求（verbatim）

> 1. 现在的 http://localhost:7860/ 界面有问题，我通过语音唤醒后没法操作，也没有操作记录（a. 只要语音唤醒后就应当有记录 b. 即使用户没有访问网页端，记录也该留存到sqlite中 c. 现在项目在语音唤醒后播放"我在听",现在明显是走sovits的,这个响应词属于固定词元,从几个备选词中随机一个,应当将这些备选词制作成固定wav或者mp3,加快回应速度） 2. 制作一个start_all.bat 的启动脚本 3. 先记入design再开工

## 实施记录

**T7 事件记录 + SQLite**
- 新增 `jarvis/events.py`：`EventLog` 类，DB `jarvis/data/events.db`（WAL），表 `events(id, ts, kind, text, source)`；`log()` 永不抛异常。
- `jarvis/main.py`：模块级 `event_log`；埋点：
  - `_handle_wake_inner`：唤醒事件落库 + 新增 WS `wake` 类型广播（在 STT 之前）
  - 转写为空 → system「没听清」
  - 语音停止指令 → system
  - `_process_request(user_text, source)`（新增参数）：user/assistant 各落一条，source=voice|web
  - `handle_wake` 异常 → system 错误
  - `main()` 启动 → system「上线」
- `jarvis/web.py`：`GET /api/events?limit=N`；WS chat 线程向 `_process_request` 传 `source="web"`。
- `jarvis/static/index.html`：WS 连接后拉取 `/api/events`（user/assistant → 聊天区，wake/system → Live 面板，带 `[MM-dd HH:MM]` 前缀）；新增 WS 类型 `wake`；Live 空态文案改 `RECORDS STANDBY`。

**T8 固定应答词 wav**
- `config.yaml`：新增 `tts.ack_dir: jarvis/data/ack`、`tts.ack_phrases`（5 句）。
- 新增 `_gen_ack_wavs.py`（gitignored）：经 GSV :9880 合成写入 `jarvis/data/ack/ack_01..05.wav`；实际运行 5/5 成功，每条 ~2.0–2.6 s（24 kHz int16）。
- `jarvis/tts.py`：新增 `play_ack_wav()` — 随机取 wav 本地 sd.play（可被 stop_speaking 打断）；目录为空时回退实时 `speak("嗯？我在听。")`。
- `main.py` `_handle_wake_inner`：原 `_speak_if_unmuted("嗯？我在听。")` 替换为静音判断 + `play_ack_wav()`（不再走实时 SoVITS）。

**T9 start_all.bat**
- 新增根级 `start_all.bat`：chcp 65001；端口占用检查告警（9880/7860）；`start` 两个独立窗口 —— GSV（`GPT-SoVITS-main/api_v2.py`，.venv-gsv）与 Jarvis（HF_ENDPOINT=https://hf-mirror.com、HF_HOME=<仓库>\.hf-cache、HF_HUB_DISABLE_XET=1，`.venv` python -u -m jarvis.main）；llama.cpp 不纳入（用户自启）。
