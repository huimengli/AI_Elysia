## 二、`_url_keys` 判据的缺陷（本轮定因）

`jarvis/tools/app_control.py` L129-142 `_url_keys()`：`keys = {netloc, netloc 首段}` + query 关键词。
视频 URL `https://www.bilibili.com/video/BV1Ki4y1y7HC` → keys 只有 **`{'www', 'www.bilibili.com'}`**。
B 站视频页标题尾部是「**_哔哩哔哩_bilibili**」，**不含 `www.bilibili.com`，也不含 `www`** → 匹配必失败：

- `open_url` 的后校验 → **成功被判失败**（假阴性，本轮实测）
- `navigate_url` 的复用选窗 → 站点匹配选不到 jarvis 窗口（只能靠 pid，退化）

**方案（不造新约定）**：keys 追加**注册域二段**（`netloc.split('.')[-2]`，如 `www.bilibili.com` → `bilibili`），
`localhost` 等单段名保持原样；标题含 `bilibili` 即可命中。修完重跑 3 轮（Q33 第 3 条口径）。

## 三、播放态判据（本轮定为可执行口径）

- **必须两次读数、时间前进**才算"真在播"；单次读数、卡片时长标签、按钮形状都**不算**（本轮自曝教训）
- **地址栏 / 窗口标题**是导航判据；**进度条时间前进**是播放判据，二者分开记
- 视觉提示词要**短且单任务**（本轮第 2 次调用回显提示词 = 提示词过长时模型退化）

- **状态**：**假阴性定因 + 判据口径落盘**；`_url_keys` 修复与 3 轮重跑见 `todo.md`
