## 追加节（12:12）：实测缺陷清单（全部是测量证据，不是设计偏好）

**读法**：共用浏览器 `dsh_browser_open` + `dsh_browser_a11y/state/execute`（**零截图**）；窄窗口量测走 Playwright MCP 的 `browser_resize` + `browser_evaluate`（那是另一个页面实例，量的是同一份 CSS）。

1. **窄窗口布局崩坏**（560×520，正是共用浏览器侧栏的窄面板场景）：唯一媒体查询是 `prefers-reduced-motion`，**没有任何断点**；`.main{height:calc(100vh - 92px)}` 假设 header 高 92px，窄窗口 header 换行到 **174px** → `mainBottom 618 > 520`，**输入栏底部 585、发送按钮被裁到视口外**、`#input` 宽只剩 **45px**（几乎不可用）、`document.body.scrollWidth > innerWidth`（水平溢出）被 `body{overflow:hidden}` **吞掉，用户滚不到也看不到**。宽窗口（1386×800）不溢出，所以这条只在窄面板/分屏时暴露。
2. **断线时「发送」= 界面层静默假成功**（实测 readyState 1→2 期间点发送）：消息气泡出现、输入被清空、状态文本仍是「待命中」、离线灯不亮、活动条不出现、3 秒重连后没有任何补发提示。根因：`send()` 只判 `!ws`，`ws` 对象在 close 后仍是真值，`ws.send()` 在 closing 态不抛异常 → 消息进了 UI，服务端永远没收到。
3. **12 个快捷按钮标签中文、指令英文**：实测点「时间」→ 用户气泡显示 `What time is it?`。页面 `lang=zh-CN`、状态中文、工具标签中文，用户看到的自己的话是英文。
4. **「播放音乐 / Open Spotify」在这台机器上必然失败**：应用表 227 条里 `spotify`/`音乐`/`云音乐`/`网易`/`QQ` **全部 0 条**；表里存在的是 记事本(`notepad.exe`)/画图(`mspaint.exe`)/计算器(`calc.exe`)/设置(`ms-settings:`)/截图工具(`SnippingTool.exe`)/终端(`wt.exe`) → 快捷按钮应换成**表里真实存在的应用**。
5. **活动条默认文案英文** `PROCESSING`（`showActivity` 还做 `toUpperCase()`）。
6. **可访问性实测**：`document.querySelectorAll('[aria-live]')` **= 0**（状态变化不会被读屏播报）；`select#modelSelect` 的可访问名是 option 拼接「llama.cpp (Local)Ollama (Local)」（不是标签）；`#muteBtn` 可访问名是 emoji `🔈`。
7. **副作用披露**：我注入的断线测试短语「断线后发送2」被模型当任务执行，产生 **3 次写文件尝试**，全部被路径白名单/路径不存在拒绝（`C:\Users\JarvisTest\Desktop\重启后发送2.txt`、`D:/重启后发送2.txt`、`桌面/重启后发送2.txt`），**没有产生任何文件**。另外点击快捷按钮时踩到 `.tab-panel{display:none}`：非活动 tab 里的按钮**坐标点击是空点**（这是正常行为，不是缺陷，但说明坐标点击在这页不可靠）。
