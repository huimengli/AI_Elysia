# 2026-11-09-21-19-29 start_all.bat 改 ASCII/CRLF + 用 start 开三个 cmd 窗口

- 提出时间：2026-11-09 21:19:29（实测 `TIME=21:19:10` 后取需求时刻）
- 提出人：用户原话：「1. start_all.bat 应当是CR LF换行格式 ASCII编码 2. start_all应该通过start打开三个(或者更多)cmd界面」

## 现状实测（`.tmp\bats\time1.log`）

- `len=2395`、`CR=56`、`LF=56` → **换行已是 CRLF**，这一条已满足；
- `nonASCII=250` → 文件里含非 ASCII 字节（`rem` 框线字符 `─` + 中文「爱莉希雅」），**不满足 ASCII 编码要求**；这也是 `read` 直读 `start_all.bat` 报 `invalid UTF-8 text` 的原因；
- 现有三处 `start "llama.cpp :8080" cmd /k ( ... )` 用**括号包裹多行复合命令**，这种写法在 `start` 后不可靠（`cmd /k` 收到的是以 `(` 开头的串，分组与引号解析易出问题），且窗口一关服务即消失、重复双击会因端口占用产生多余窗口。

## 方案

1. **纯 ASCII + CRLF**：所有注释与提示改英文，去掉框线字符与中文；用 PowerShell `Set-Content -Encoding Ascii`（行连接为 `\r\n`）生成，落盘后统计字节验证 `nonASCII=0` 且 `CR==LF`。
2. **每个服务一个独立 cmd 窗口**：统一改写成可靠的单行形式 `start "标题" cmd /k "cd /d ... & set ... & 程序"`，共 4 个窗口：
   - `llama.cpp :8080`
   - `GPT-SoVITS :9880`
   - `AiliXiya :7860`（Jarvis，带 `HF_ENDPOINT/HF_HOME/HF_HUB_DISABLE_XET`）
   - `Jarvis Status`（第 4 个窗口，PowerShell 每 5 s 显示 `8080/9880/7860` 监听 pid 与 `GET /api/health`，满足「三个或更多」）
3. **幂等**：`netstat` 检查到端口已 `LISTENING` 时打印 `[Skip] :NNNN already in use` 并跳过启动该服务，避免双击两次堆出重复服务/窗口。
4. 验证 3 轮写入 `tests/2026-11-09-21-19-29_cc/`，结论累积到 `tests/opinion.md`：① 字节属性（ASCII、CRLF、`start` 条数）；② 服务在跑时双击 → 新实例按 `[Skip]` 跳过、只多出状态窗口、pid 无重复；③ 停掉 `:7860` 后双击 → Jarvis 窗口真实打开且 `:7860` 由**新 pid** 重新监听（证明 `start` 分支可用）。全程零截图（`tasklist`/`netstat`/`curl` + 窗口标题文本）。
